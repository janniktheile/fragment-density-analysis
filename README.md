# Fragment Density Analysis

Python tools for fragment-resolved analysis of Gaussian Cube files and real-time time-dependent density functional theory (RT-TDDFT) simulations.

---

## Overview

This repository provides Python scripts for analyzing electron-density data obtained from RT-TDDFT simulations.

The software supports two complementary analysis workflows:

* **Projected density-difference visualization** from Gaussian Cube files.
* **Fragment-resolved electron-population analysis** using a smooth distance-based real-space partitioning scheme.

Although the scripts were developed for the asymmetric donor–acceptor oligomer **A1–D–A2(3F)**, they can be adapted to other molecular systems by modifying the input files and fragment definitions.

---

## Features

* Fragment-resolved integration of Gaussian Cube files
* Smooth distance-based (Voronoi-like) fragment partitioning
* Electron-density difference calculations
* Projected two-dimensional density maps
* Time-dependent fragment population analysis
* Charge-redistribution visualization

# Workflow 1 – Projected Density-Difference Maps

## Step 1 – Generate Density-Difference Cube Files

`density_difference.py`

This script generates normalized electron-density difference Cube files from two input wavefunction Cube files.

Typical output:

```text
difference_density_normalized.cube
difference_density_normalized_summary.txt
```

The summary file reports

* wavefunction normalization,
* density integrals,
* density extrema,
* total density-difference integral.

The script should be executed for every simulation snapshot that will later be visualized.

---

## Step 2 – Generate Projected Density Maps

`analyze_density_laser.py`

This script visualizes projected density-difference maps from one or two simulation series.

Typical applications include comparisons of

* different laser intensities,
* moving vs. frozen nuclei,
* selected propagation times.

The script generates publication-quality figures containing

* projected density-difference maps,
* molecular overlay,
* Gaussian laser pulse,
* shared color scale,
* optional analysis summaries.

Typical output:

```text
*_2D_projected_two_series.png
```

The projected fragment values reported by this script are intended as qualitative trend metrics. Quantitative fragment-resolved electron populations should be obtained using `fragment_cube_partition.py`.

# Workflow 2 – Fragment-Resolved Electron Populations

`fragment_cube_partition.py`

This script computes fragment-resolved electron populations from time-dependent Gaussian Cube files.

Fragments are defined by user-specified atom indices.

Example:

```bash
python fragment_cube_partition.py \
    "td.*/density.cube" \
    --fragment "A1:1-6" \
    --fragment "D:7-20" \
    --fragment "A2:21-32" \
    --reference first \
    --output fragment_integrals.csv
```

Example fragment definition:

```text
A1 : atoms 1–6
D  : atoms 7–20
A2 : atoms 21–32
```

The script also supports arbitrary fragment names, for example

```text
Donor
Bridge
Acceptor
```

The output CSV contains

```text
frame
step
filename

A1
D
A2

delta_A1
delta_D
delta_A2

total
sigma
grid_spacing
stride
```

The `total` column can be used to verify electron-number conservation during the simulation.

A detailed mathematical description of the smooth fragment-partitioning scheme is provided in

```text
docs/methods.md
```

# Workflow 3 – Plot Time-Dependent Fragment Populations

`delta_q_t_plot.py`

This script reads the CSV generated by `fragment_cube_partition.py` and produces time-dependent fragment-population plots.

Typical quantities include

* ΔA1
* ΔD
* ΔA2
* time-averaged fragment populations

Example output:

```text
time_averaged_charge_redistribution.png
```

# Notes

* Atom numbering follows the order of atoms in the Gaussian Cube files.
* Fragment indices are specified using **1-based atom numbering**.
* All Cube files within one analysis should use identical grids and atom ordering.
* System-specific file paths should be adapted before running the scripts.
